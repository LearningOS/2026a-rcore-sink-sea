# Lab 3：进程管理与调度

## 1. 实验目标

本实验在独立地址空间的基础上引入进程生命周期和父子关系，主要完成以下内容：

1. 理解进程控制块、PID、内核栈和父子进程关系。
2. 理解 `fork`、`exec`、`waitpid` 和僵尸进程的协作过程。
3. 实现直接创建新进程的 `spawn` 系统调用。
4. 实现进程优先级设置和 stride 调度。
5. 将上一章的跨页时间写入、`mmap` 和 `munmap` 适配到进程模型。

## 2. 进程生命周期

每个进程由 `Arc<TaskControlBlock>` 管理。TCB 中不变的部分包括 PID 和内核栈，可变部分放在 `UPSafeCell<TaskControlBlockInner>` 中，包括任务上下文、地址空间、父子关系、退出码和调度信息。

进程退出时不会立刻销毁 TCB，而是进入 `Zombie` 状态并保存退出码。父进程调用 `waitpid` 后，从 `children` 中移除对应僵尸进程，读取退出码，此时最后一个强引用被释放，PID 和内核栈等资源才真正回收。父进程提前退出时，其子进程会被托管给初始进程。

## 3. `spawn` 实现

`spawn` 与 `fork` 后再 `exec` 不同：它不复制父进程地址空间，而是直接根据目标 ELF 创建一个全新的地址空间和陷阱上下文。实现流程如下：

1. 根据当前页表翻译用户传入的程序名。
2. 在内核内置应用表中查找对应 ELF 数据，不存在时返回 `-1`。
3. 调用 `TaskControlBlock::new` 分配 PID、内核栈并加载 ELF。
4. 设置新进程的父指针，并将新进程加入父进程的 `children`。
5. 将新进程加入就绪队列，向父进程返回子进程 PID。

这种实现只构造目标程序实际需要的页面，避免了 `fork + exec` 先完整复制、随后又丢弃地址空间的额外开销。

## 4. Stride 调度

每个进程维护两个调度字段：

- `priority`：进程优先级，默认值为 16；
- `stride`：进程已经累计的调度步长，初始为 0。

调度器每次选择就绪队列中 `stride` 最小的进程。选中后按下式增加其 stride：

```text
pass = BIG_STRIDE / priority
stride = stride + pass
```

优先级越大，每次增加的 pass 越小，进程在相同时间内被选中的次数越多。实现使用 `u128` 保存 stride，降低长时间运行时溢出的风险。`fork` 出的子进程继承父进程的优先级和当前 stride，避免新进程总从零开始而短时间独占 CPU；`spawn` 创建的独立程序使用默认调度参数。

`set_priority` 只接受大于 1 的值。合法值写入当前进程的 TCB 并原样返回，零、负数和 1 均返回 `-1`。

## 5. 地址空间功能迁移

本章继续使用带权限检查的用户缓冲区翻译函数实现 `get_time`，因此 `TimeVal` 跨页时仍能正确写入。`mmap` 在建立映射前检查地址、权限和区间冲突；`munmap` 先验证整个区间，再清除页表项和释放物理帧。

与上一章相比，解除映射还会把原 `MapArea` 按需保留为左、右两个区域。这样进程在部分解除映射后执行 `fork` 时，地址空间复制只遍历仍然有效的页面，不会访问已经解除映射的页表项。

## 6. 测试

使用以下命令运行第五章检查器：

```bash
make -C ci-user test CHAPTER=5
```

测试重点包括：

- `fork` 的父子返回值和地址空间复制；
- 子进程退出、僵尸状态、`wait` 与 `waitpid`；
- 连续创建并回收多个 `spawn` 子进程；
- 合法和非法优先级参数；
- 多个不同优先级进程的 stride 调度；
- 第三、四章时间、调度和地址空间功能的回归测试。

最终检查结果为 `15/15`，三个累计实验报告均通过完整性检查。六个 stride 测试进程的 `count / priority` 比值接近，符合按优先级比例分配 CPU 时间的预期。

## 7. 实验总结

本实验把“可调度任务”扩展成具有完整生命周期和亲缘关系的进程。`spawn` 展示了直接构造进程比组合已有系统调用更高效的场景，而 stride 调度则用较小的实现代价提供了按权重分配 CPU 时间的能力。实现中还需要特别注意资源所有权：父子关系使用强、弱引用避免循环，僵尸进程由父进程回收，地址空间修改则必须保持 `MapArea` 与页表的一致性。
