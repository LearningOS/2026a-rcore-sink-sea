# Lab 2：地址空间与内存映射

## 1. 实验目标

本实验在第三章分时多任务内核的基础上引入 Sv39 虚拟内存，主要完成以下工作：

1. 理解页表、虚拟页号、物理页号和页表项权限位之间的关系。
2. 在内核中安全地访问用户地址空间，实现跨页的 `get_time`。
3. 使 `sys_trace` 根据用户页表检查地址和读写权限。
4. 实现匿名内存映射 `mmap` 和解除映射 `munmap`。
5. 保留第三章按任务统计系统调用次数的功能。

## 2. 用户地址翻译

进入系统调用后，内核运行在内核地址空间，不能直接把用户虚拟地址当作内核指针使用。因此实现了带权限检查的用户缓冲区翻译函数。该函数逐页完成以下检查：

- 地址加法不能溢出，地址必须是合法的 Sv39 规范地址；
- 页表项存在并且具有 `V` 标志；
- 页表项必须具有 `U` 标志，防止用户指针访问内核页；
- 读取要求 `R` 权限，写入要求 `W` 权限。

检查通过后，根据页内偏移把一个用户缓冲区拆分成多个物理页切片。这样既能处理普通缓冲区，也能处理跨页对象。

## 3. `get_time` 与 `sys_trace`

### 3.1 跨页写入 `TimeVal`

`TimeVal` 包含秒和微秒两个 `usize`。如果用户传入的结构体地址靠近页尾，两个字段可能位于不同页面。实现中先在内核栈上生成完整的 `TimeVal`，再把它转换为字节切片；确认所有目标页面都可写后，逐段复制到用户空间。该顺序也避免了只写入一部分结构体后才发现下一页无效的问题。

### 3.2 安全的 trace 读写

`sys_trace` 的读请求只接受用户可读页，写请求只接受用户可写页。未映射地址、内核地址、非规范地址和权限不匹配的地址均返回 `-1`，不会在 S 态直接解引用错误地址。

系统调用计数仍在统一分发入口增加，因此查询 `SYSCALL_TRACE` 时，本次查询已经被计入结果。每个 `TaskControlBlock` 保存独立计数数组，任务切换不会混淆统计信息。

## 4. `mmap` 设计

`mmap(start, len, prot)` 的实现步骤如下：

1. 拒绝长度为零、起始地址未按页对齐、地址溢出或非规范地址的请求。
2. `prot` 只允许最低三位，分别表示读、写、执行；权限为空或包含未知位时返回 `-1`。
3. 按 `[start, start + len)` 计算覆盖的虚拟页，逐页确认当前没有有效映射。
4. 为每一页分配物理帧，建立带 `U` 标志和指定权限的页表项。

长度不要求是页大小的整数倍，末尾不足一页时按向上取整映射。映射前先检查完整区间，避免发生部分映射。

## 5. `munmap` 设计

`munmap(start, len)` 同样要求起始地址页对齐、长度非零且地址合法。解除映射前先检查区间中的每一页：所有页面都必须是有效用户映射，否则整个操作返回 `-1` 并保持原映射不变。

验证通过后，逐页清除页表项，同时从对应 `MapArea` 中移除 `FrameTracker`，使物理页可以被回收。查找时优先选择最近加入且实际拥有该物理帧的区域，从而支持同一虚拟地址在解除映射后再次映射。

## 7. 实验总结

本实验中最重要的变化是不能再把用户指针视为可信的普通指针。系统调用需要结合当前任务的页表，对用户地址逐页翻译并检查权限。`mmap` 和 `munmap` 还需要先验证整个区间再修改页表，才能保证失败时不留下部分完成的状态。通过这些实现，任务拥有了相互隔离的地址空间，错误的用户访存也可以由内核终止当前任务，而不会直接破坏内核数据。
